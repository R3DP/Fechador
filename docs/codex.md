## Usar um plano ChatGPT em vez disso (Codex)

Claude é o padrão e não precisa de mudança. Se preferir gastar um plano ChatGPT (Plus, Pro, Business, …), o Sellbird pode pensar através do [Codex CLI](https://developers.openai.com/codex) — ainda uma assinatura, nunca cobrança por token de API.

```bash
npm install -g @openai/codex@0.159.3   # a versão do Codex que o Sellbird verificou (veja Requisitos)
codex login                            # escolha "Sign in with ChatGPT" — logins por chave de API são recusados
```

Depois escolha **codex** em `sellbird setup` (ele sugere `gpt-5.5`), rode `sellbird train <url> --provider codex --model gpt-5.5`, ou adicione à sua configuração:

```yaml
brain:
  provider: codex
  model: gpt-5.5         # ou um ID de modelo Luna, Sol ou Terra disponível
  reasoning_effort: ""   # opcional: minimal | low | medium | high | xhigh
```

O que saber:

- **É um ou outro.** O Sellbird usa exatamente o provedor que você configurar. Se o Codex falhar, a chamada falha com uma mensagem clara no log; ela nunca cai de volta para o Claude (nem para uma chave de API). Uma máquina só com Codex não precisa do Claude instalado.
- **Sua configuração do Codex fica intocada.** Cada chamada roda processos `codex` descartáveis em um home temporário privado e um workspace vazio, então seu `~/.codex/config.toml`, servidores MCP, plugins, hooks, skills, `AGENTS.md` e memórias nunca são carregados, e a escolha de modelo do Sellbird nunca muda o seu padrão pessoal do Codex.
- **Sem ferramentas, verificado antes de cada prompt.** Os prompts contêm texto não confiável (respostas de prospects, páginas raspadas), então o modelo não pode ter nada com que agir. O Sellbird desativa todo recurso do Codex que fornece ferramentas, busca na web, subagentes, hooks, skills e instruções de projeto, inicia a thread sem ambiente de execução e então confere os próprios relatos do Codex (configuração efetiva, tipo de conta, configurações da thread, status do MCP, hooks) antes de enviar qualquer coisa. Qualquer item que ele não consiga confirmar interrompe a chamada. Durante o turno, qualquer tentativa de chamada de ferramenta, pedido de aprovação ou item que não seja texto mata o runtime. Um sandbox somente leitura também é aplicado, apenas como proteção extra.
- **Seu login só vai para a OpenAI.** Antes de colocar seu login no runtime, o Sellbird inicia o Codex sem ele e confere que as requisições iriam para o provedor OpenAI embutido e o endpoint padrão do ChatGPT. Qualquer provedor personalizado, provedor embutido sobrescrito, URL base, exportador de telemetria ou outro endpoint em qualquer camada de configuração do Codex (por exemplo `/etc/codex/config.toml` ou uma configuração gerenciada) interrompe a chamada ali.
- **Tratamento do login.** O Sellbird suporta o armazenamento de credenciais em arquivo do Codex (`~/.codex/auth.json`, ou `$CODEX_HOME/auth.json`, modo `600`): o padrão, a menos que você tenha configurado um keyring do sistema operacional. Armazenamento em keyring não é suportado. A cada chamada o Sellbird lê esse arquivo (somente leitura, nunca escrevendo ou movendo) e entrega ao runtime uma cópia privada *sem o refresh token*, apagada depois da chamada. O Codex portanto não consegue alterar ou renovar seu login real. Quando o login expirou, ou está no prazo de renovação rotineira do Codex (após cerca de 8 dias), as chamadas ao Codex param com "Your Codex login has expired or is due for renewal". Use o Codex uma vez você mesmo (ele renova o login automaticamente) ou rode `codex login`, e o Sellbird capta o login renovado na chamada seguinte. O Sellbird nunca o renova para você.
- **Modelos.** Defina `brain.model` com um ID exato de modelo do catálogo da sua conta, incluindo modelos Luna, Sol e Terra como `gpt-5.6-luna`, `gpt-6.1-sol` e `gpt-5.6-terra`. `gpt-5.5` continua suportado quando presente no catálogo da sua conta e é a sugestão do setup. O Sellbird cria uma cópia privada do catálogo que preserva as capacidades do modelo ao selecionar o modo direto de ferramentas e remover ferramentas experimentais. O modelo não recebe ferramentas sob o confinamento do Sellbird. Um `model` em branco seleciona o modelo listado de maior prioridade que consegue usar esta configuração; modelos ocultos exigem um ID explícito. Um modelo explícito é usado exatamente ou a chamada falha. IDs de modelo desconhecidos e modos de ferramenta não reconhecidos são rejeitados. A disponibilidade depende da sua conta ChatGPT.
- **Cota.** O gate de orçamento e o dashboard leem do Codex as janelas reais de limite de taxa do seu plano ChatGPT, para o bucket de limite que se aplica ao seu modelo, e as comparam com `usage.max_daily_claude_percent`. Se o Codex relatar que o uso está bloqueado, ou se uma chamada falhar por limite de uso do plano, o Sellbird trata o plano como cheio (mesmo quando nenhuma janela é relatada) e para as chamadas ao Codex por uma hora. Se os limites não puderem ser lidos, o dashboard e `sellbird usage` mostram "Quota unavailable" e o orçamento recorre à própria contagem diária de chamadas do Sellbird. O uso é registrado por provedor; chamadas ao Codex são registradas com tokens mas sem custo em dólar, porque o plano não é cobrado por token.
- **Quando o Codex não pode ser usado, o Sellbird pausa em vez de adivinhar.** Antes de cada heartbeat, o Sellbird confere tudo o que uma chamada precisa exceto o próprio prompt: a versão do Codex CLI, o isolamento, seu login (expirado ou no prazo de renovação), sua conta ChatGPT, e que seu modelo configurado consegue rodar sem ferramentas. Nenhum prompt é enviado, então nada é usado do seu plano além de uma rápida verificação da conta. Se algo estiver errado, o ciclo inteiro é pulado: nenhuma resposta é lida ou marcada como tratada, nada é redigido ou enviado. A linha do log, `sellbird status` e o card Actions do dashboard dizem "Codex paused" e o motivo. Se o Codex parar de funcionar no meio de um ciclo (por exemplo o plano atinge seu limite de uso), a resposta que está sendo tratada fica exatamente como estava, para uma nova tentativa limpa, não escalada, meio-registrada ou perdida, e aquele ciclo não envia nada. Corrija a causa (geralmente `codex login`), e o Sellbird retoma no próximo heartbeat: um login renovado ou CLI reinstalado é percebido imediatamente, uma pausa por limite de uso termina após uma hora, e outras correções são captadas em até 30 minutos. `sellbird status --check` roda a mesma verificação sob demanda e sai com código diferente de zero se falhar. Falhas breves (um travamento ou timeout) apenas pulam um ciclo. O Sellbird nunca cai de volta para o Claude ou uma chave de API.
- **Requisitos.** **macOS ou Linux**, Codex CLI **0.159.3** exatamente, e Node.js para seu pacote npm. **Windows não é suportado para o Codex:** o Sellbird o recusa ali antes de ler seu login; use o provedor Claude no Windows. O Sellbird confere a versão do Codex antes de cada chamada e recusa qualquer outra versão, incluindo as mais novas, porque um Codex diferente pode adicionar ferramentas que o confinamento do Sellbird não conhece. O suporte a uma nova versão vem com uma atualização do Sellbird. O uso ao vivo com uma conta ChatGPT real foi verificado em macOS e Linux ARM64. As suítes offline também passaram em Linux x86-64 sob emulação de CPU; a CI cobre Linux e macOS. A imagem Docker traz apenas o Claude CLI, então o Codex não é suportado no Docker. Para reverificar o confinamento offline contra seu CLI instalado, sem credenciais ou rede: `SELLBIRD_CODEX_CLI_TESTS=1 pytest tests/test_codex_cli_surface.py`.
- **Sobrecarga.** Cada chamada confere a versão do CLI, inicia o Codex uma vez sem seu login para verificar sua configuração, lê o catálogo de modelos e então o inicia de novo para rodar o prompt; a verificação de cada heartbeat faz o mesmo sem o prompt. Isso adiciona alguns segundos por chamada, e as chamadas ao Codex de um Brain rodam uma de cada vez.
